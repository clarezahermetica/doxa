## 1. Executive assessment

DOXA operates an offline research lifecycle with distinct participant identities,
versioned sources, contexts, claims, objections, responses, revisions, adjudication,
evaluation, checkpoints, controlled branches, comparison and inspectable exports.
The same controller and SQLite history serve the CLI and existing Textual application.

This is procedural and storage validation. It is not empirical evidence of improved
reasoning, reliable autonomous science, or broad provider compatibility. Native and
compatible inference adapters have deterministic HTTP fixtures; live acceptance remains
**pending authorization** naming provider, exact model, spend limit and disclosure scope.

The project is ready for the owner's GitHub synchronization review as an experimental
offline-verified baseline, with the live and distribution limitations below. The owner
should review the complete cumulative working tree before synchronizing GitHub.
Pass 4 neither commits nor publishes it. README remains the owner's unchanged file.
The installed v17 application is preserved; candidate testing uses isolated installations.

## 4. Scientific findings

The oracle reference is read/update/delete = T/T/T for `invalidate_all`, T/F/T for
`stale_on_update`, T/T/F for `stale_on_delete`. Despite its historical name,
`invalidate_all` removes the affected key on update/delete; it is not a global flush.
These finite results establish neither general cache correctness nor speed superiority.

The fixture's false opening is linked to a real S2 span. This deliberately demonstrates
that citation presence and a valid span can coexist with a false claim. B/C contain a
scripted evidence-based qualification and C also retains/rejects a misleading objection.
The claimed improvement is written into fixtures; it is not a measured model effect.

Citation presence, span validity, entailment, factual correctness, agreement and procedural
completion are separate observations. The evaluator reports counts and explicit objection
state; semantic contradiction frequency and entailment remain unmeasured. Known opposing
fixture claims have a preregistered finite reference, not an invented automatic prose oracle.
No causal or provider-family conclusion follows from changing participant counts/scripts.

In the finite companion, the accepted-correction branch passed 5/6 accumulated checks and
the rejected-correction branch passed 4/6; final task success was 1/1 versus 0/1. These
include earlier failures, not six independent benchmark problems. Memory retrieval returned
one promoted item before revocation and none afterward. Both branches recorded zero model
calls; elapsed local branch times were 3.29s/2.76s, not provider latency. Metrics with a zero
denominator remain null. This verifies the finite measurement machinery, not autonomous
model discovery of a correction.

The standard-library inspector independently checks ZIP member hashes, event/author IDs,
claim versions, contexts, evidence spans, source hashes, branch/checkpoint relationships.
It runs with `python -I -S` outside the source workspace and never executes archive contents.
The durable A/B/C archives verified 14/17/26 files and 4/5/11 citation spans respectively
(including the analysis branches). The finite companion independently verified 18 files.
This reproduces preserved history, not stochastic model generation. Corrupt archives fail.

## 6. Security and operational findings

The focused credential remediation follows the Codex Security fix-finding workflow with
independent read-only investigation and a separate candidate review. Managed evidence is
retained separately from publishable source. Only dummy credentials were used as triggers.

Research-created authentication aliases were not covered by name-suffix discovery. The
shared guard now considers incoming and historical profile references, protected values,
and shadowed dotenv/process copies. JSON escapes and overwritten duplicate members are
checked; original compressed DOCX metadata is checked before artifact publication. JSON,
JSONL and ZIP exports refuse known credentials without rewriting old history. Provider
redaction uses the shared rules; response/request validation precedes artifact writes.

A large-batch regression revealed a second SQLite reader could block its own transaction;
the internal append guard now reads credential references through that active transaction.
The reproduced 1,050-record case passes after correction. No accounting outcome is invented
when credential validation rejects a response; uncertain operations require review.

This is known-credential detection, not universal data-loss prevention. Arbitrary encrypted,
steganographic or opaque binary content is not certified secret-free. Imported research
materials can themselves be private; review archives before sharing. Never infer that a
source is trusted instructions, correct evidence, or safe to disclose merely from import.

Existing bounds retain agent/tool permissions, separate external authorization, redirect/
SSRF checks for research fetches, loopback-only unbilled inference, fixed native provider
origins, bounded document subprocesses, artifact-address validation and disabled generated
code. Prompt boundaries reduce instruction confusion; they cannot guarantee LLM immunity
to prompt injection. No unrestricted execution, network permission or provider was added.

An actual backup publication inside OneDrive failed with WinError 5; it preserved the
source. The same exposed commands succeeded outside the sync tree. The terminal's existing
sync warning remains appropriate. No workspace was moved. Concurrent synchronized writers
and cloud conflict resolution are not certified safe.

The final package manifest has 149 payload entries plus the manifest itself. Checks found
no known current credential values in the 238-file proposed source inventory, raw package
payloads or DOXA Python code constants, and no personal absolute `co_filename` paths in
DOXA code. Required Textual, Moss/Moss core, pypdf, HTTPX, Alembic and SQLAlchemy modules
are present; desktop/webview modules are excluded. This is a concrete inventory/known-key
check, not a claim to detect every possible private phrase or encoded secret.
An additional owner-path check over all 2,052 frozen Python modules and raw payloads also
found no owner-specific absolute path. No imported module code was executed by that check.
