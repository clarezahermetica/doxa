## Principle

DOXA should not bind its research architecture to one model vendor. Roles are assigned to provider/model adapters, and each adapter declares the features it actually supports.

## Provider classes

<b>Hosted API</b> — external inference service accessed with credentials.

<b>Remote self-hosted</b> — open-weight model served on a GPU service such as RunPod using an HTTP endpoint.

<b>Local inference</b> — optional for hardware that can support it; not required for the Cal Hacks system.

## Adapter capability declaration

Every adapter should report:

- Provider and exact model identifier.
- Structured-output support: native, constrained/prompted, or unavailable.
- Tool calling: native, emulated via structured actions, or unavailable.
- Streaming availability.
- Context limits if known.
- Usage/token reporting availability.
- Seed/determinism controls if exposed.
- Timeout/retry behavior.
- Cost metadata or unknown status.

## Role assignment

Executor, Skeptic, Researcher, and Archivist can use different models or the same model under separate role instructions. The experiment record preserves the exact assignment.

## Cross-model comparisons

Different model families can reduce some correlated behavior but do not guarantee independence. DOXA should treat model diversity as an experimental variable, not proof of independent reasoning.

## Reliability behavior

Provider errors should become typed events. The runtime should support bounded retries, explicit timeouts, model-call cancellation where possible, and a clean distinction between task failure and infrastructure failure.

## Reproducibility

Log exact provider/model IDs and settings exposed by the service. If a provider silently updates a model behind a stable alias, note that the external service limits perfect reproducibility.

## Open decisions

Specific Executor and critic models, primary hosted API, first open-weight model, and whether RunPod serves through vLLM or another compatible server remain to be benchmarked before implementation.

## Low-cost model policy — October 12, 2026

- <b>One physical model is sufficient</b> for Solo Direct and Solo Deliberative, even if it fills Proposer, Skeptic, Defender, Archivist and Adjudicator roles in separate calls. Collaborative/adversarial sessions may assign GPT and Gemini to different roles, but multiple providers are an experimental choice, not a requirement.
- Ship hosted adapters for OpenAI and Gemini, with a provider-neutral configuration for OpenAI-compatible optional vLLM/RunPod inference. Begin with budget-conscious small models; record exact IDs/settings/pricing version and permit per-role assignment. Claude remains an optional future adapter, not a hackathon dependency.
- Independently configured request caps, max critique rounds, retries, context size, token budgets, latency/timeouts and allowed tool calls. Reserve estimated cost before calling; enforce run cap and global <b>\$75 hackathon cap</b>; warn at thresholds; stop before known further charges exceed the remaining allowance. Track uncertain charges rather than pretending estimates are exact. Set vendor billing limits separately where available.
- Compare same-model and cross-family critics under explicitly documented compute, evidence access and seed/sampling settings. Different providers are not independent verifiers; use executable or curated evidence wherever available.
- No secret-bearing files/logs, no third-party telemetry. Remote inference is opt-in and sends selected task data off the machine; pass only minimum necessary context.
