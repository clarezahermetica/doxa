# Core System — False Critic

## Purpose

False Critic tests whether an agent can respond appropriately to criticism without assuming that criticism is correct merely because it is confident, adversarial, or generated by another model.

## Challenge classes

A controlled benchmark may include:

- Valid criticism of an incorrect decision.
- Invalid criticism of a correct decision.
- Partially justified criticism requiring qualification.
- Invalid criticism of an already incorrect decision, requiring the agent to reject the critic and still continue checking its own answer.
- Underdetermined cases where the correct behavior is to preserve uncertainty or retrieve additional evidence.

## Structured critic message

A challenge should include the target claim or decision ID, critic identity, objection, supporting evidence or requested evidence, confidence or uncertainty where available, and the action the critic recommends.

## Response actions

The target agent may Accept, Reject, Qualify, Investigate, or Defer. These are observable response types, not judgments of correctness.

## Verification

False Critic should prefer independently checkable evidence: executable tests, task specifications, hidden evaluation cases, curated source passages, or deterministic state constraints. A second LLM can assist, but another model vote is not equivalent to verification.

## Critic reliability

The Gym should track which critic objections were ultimately supported and whether the target agent reacted appropriately. This permits comparison among self-critique, same-model critique, cross-model critique, and different critic policies.

## Acceptance tests

1. Submit a valid challenge to a wrong decision and verify revision can be triggered.
2. Submit an invalid challenge to a correct decision and verify the system can preserve the original decision.
3. Record critic evidence and link it to the target version.
4. Record the agent's response type.
5. Record independent verification separately from the critic's claim.
6. Include at least one ambiguous/insufficient-evidence case that does not force a binary answer.

## Research metric candidates

Valid-correction rate, unjustified-revision rate, critic precision, critic-induced regression rate, and unresolved-case handling.

- Expose “Challenges” contextually within the trajectory; the internal “False Critic” name is not a required product-facing label.
- Support valid, invalid, partly valid, and insufficient-evidence critic conditions; include a verified-correct solution attacked by a persuasive false critic, and an invalid objection made to an already-wrong answer.
- Log challenge target version, actor/model, supporting evidence, response, independent verifier status and cost as separate typed ledger events. Critic agreement is not ground truth.
