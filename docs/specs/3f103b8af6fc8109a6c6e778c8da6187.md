## Purpose

Self-Correction Gym is the experimental headquarters of DOXA. It captures complete observable trajectories, runs controlled comparisons, computes objective task metrics, supports detailed human labeling, and exports structured records for later analysis or training preparation.

## Trajectory definition

A trajectory includes task and environment version, agent configuration, provider/model settings, observations, claims, actions, tool results, challenges, revisions, checkpoint events, memory changes, final environment state, evaluator outputs, costs, and annotations.

## Comparison modes

- Same model, different policy.
- Solo vs collaborative vs adversarial.
- Critique without verification vs verified critique.
- Reflection-only vs rollback-enabled recovery.
- Unfiltered memory vs governed memory.
- Always-review vs adaptive intervention.
- Same starting checkpoint with alternative branches.

## Automated evaluation

Task-specific evaluators may record hidden-test pass rate, goal satisfaction, source support, state invariants, error recurrence, model/tool calls, tokens, latency, and estimated cost.

## Human annotation

Required first-release labels include:

- Overall trajectory quality using an anchored rubric.
- Evidence quality.
- Decision consistency.
- Criticism handling.
- Revision quality.
- Memory quality.
- Recovery quality.
- Efficiency.
- Pairwise preference: A, B, tie, or neither.
- Critic validity: valid, invalid, partial, uncertain.
- Revision justification: justified, unjustified, unclear.

## Provenance rule

A hidden test result, deterministic rule, human label, and LLM-generated evaluation must be stored as different types with evaluator identity and version. No field named ground truth should silently mix them.

## Export

Initial exports should be JSON or JSONL with stable IDs and enough context to reconstruct comparisons. Later adapters can transform labeled records for DPO-, KTO-, SCoRe-, or other training experiments.

## Acceptance tests

1. Save a complete trajectory.
2. Compare two trajectories sharing an initial task.
3. Compute at least one objective task metric and one process metric.
4. Save human dimensional labels and a pairwise preference.
5. Reload annotations and preserve rubric version.
6. Export machine-readable records with provenance and branch ancestry.
