### Central research question

> Under what conditions do criticism, multi-agent collaboration, reflection, checkpointed recovery, and governed memory improve an autonomous agent's later decisions — and under what conditions do those interventions create new errors?

### Product thesis

DOXA should make consequential agent behavior <b>inspectable, contestable, recoverable where the environment permits it, and experimentally comparable</b>. A model changing its answer is not automatically evidence of improvement; a critic disagreeing is not automatically evidence that the critic is right; a reflection generated after failure is not automatically a lesson worth retaining.

### Shared-history rule

All core capabilities operate over one versioned experimental history. Claims, evidence, decisions, actions, challenges, checkpoints, memories, evaluations, and human labels refer to shared identifiers. The six systems are not separate demos; they are different operations over the same trajectory.

### Initial release definition

- Epistemic Git can create, revise, inspect, and compare versioned commitments.
- The Counterfactual Engine can restore a supported environment state and execute an alternative branch.
- False Critic can process supported and unsupported challenges without treating criticism as ground truth.
- Memory Tribunal can verify, quarantine, reject, retrieve, promote, and revoke memory records with provenance.
- Self-Correction Gym can run experiments, compare trajectories, compute metrics, collect human labels, and export structured records.
- Adaptive Reflection can choose among continue, verify, retrieve, critique, reflect, roll back, escalate, and stop using an explicit first-release policy.
- Solo, collaborative, and adversarial runs work end to end.
- CLI and Studio use the same runtime and persisted experiment records.
- At least one real model backend and one restorable experimental environment work end to end.
- Previous experiments can be reloaded and inspected without losing branch history or annotations.
- The public release documents installation, configuration, limitations, experimental assumptions, and provenance.

### Working technical shape

DOXA is planned as a <b>local control plane with optional remote inference</b>. The core runtime, experiment records, annotations, and UI can live locally while model calls route through configurable API adapters or a remote GPU service. Generated code should execute inside a restricted disposable sandbox rather than directly against the host environment.
